## Ground rules
- Plain HTML/CSS/vanilla JS ES modules. No frameworks, no build step. `public/` deploys as static files.
- Animation libraries: only the self-hosted ones in `public/vendor/` (see `vendor/README.md` for versions and licenses): **GSAP** 3.15 with ScrollTrigger and SplitText, **Lenis** (smooth scroll) and **Three.js** 0.180 (minified builds; later versions ship none). Never load anything from a CDN. Site code must still work if a vendor file fails to load (guard `window.gsap`, `window.Lenis`; Three.js is a dynamic import with a 2D fallback). Reduced motion turns all of it off.
- Everything stays on-device: no uploads, accounts or analytics. MediaPipe loads from jsDelivr/Google storage, then is cached by `sw.js`. No server code: an AI coach summary was built and then removed at the user's request (it would spend their API credits). Accounts/leaderboards: don't build until the user asks.
- Pure logic, no DOM, unit-tested: `session.js`, `filters.js`, `tracking.js`, `coach.js`, `speech.js`, `circuit.js`, `history.js`, `rest.js`, `recording.js`, `scoring.js`, `geometry.js`, `exercises/*`. UI goes in `js/ui/`.
- Scoring calibration: good reps ≈ 95–100, half squat ≈ 70–76, quarter ≈ 50–58, obvious faults clearly lower. Change a curve → update `tests/scoring.test.mjs` and say why.
- Back must always stop the camera at once, in any state (`stopLive()` in `ui/live.js`). The e2e suite checks every stream ever opened has ended.
- Brand: grade gradient coral→green on navy, Unbounded + Instrument Sans. Colour tokens in `css/theme.css`.
- Clickable controls first; keyboard shortcuts are extras.
- Motion curves come from `js/ui/ease.js` (named easing graphs: `CURVE.outCubic` for WAAPI, `ease.outCubic(t)` per frame, `var(--ease-out-cubic)` in CSS). Never write a raw `cubic-bezier()` or keyword `ease` in JS; `tests/ease.test.mjs` checks it and that theme.css/site.css match.

## Commands
- `npm run dev` — serve `public/` at http://localhost:8080 (`?debug` for the readout + landmark recorder, `?cpu` to skip the GPU)
- `npm test` — all unit/engine suites (must pass before every commit)
- `npm run test:e2e` — Playwright browser suite (first time: `npx playwright install chromium`); pass a regex to run a subset: `node tests/e2e/run.mjs "camera"`; `E2E_CHANNEL=chrome` uses the installed Google Chrome instead
- `npm run sw` — **run after changing any file in `public/`**: refreshes the precache list + content-hash version in `public/sw.js` (`tests/pwa.test.mjs` fails otherwise; a missing file there breaks offline loading)
- `npm run voice` — render new/changed coach phrases with Kokoro (incremental; first run downloads ~90 MB model). **Any new spoken text must be added to `coaching.js` (and so to `js/phrases.js`) and rendered**, or `tests/voice.test.mjs` fails. Then `npm run sw`.
- `npm run eval:angles` — 2D vs 3D angle accuracy on the simulator and on `tests/fixtures/*`
- `node tools/make-library.mjs` — regenerate `public/exercises.html` (the exercise library) after changing exercises, coaching lines, tips or skills; `node tools/make-whatsnew.mjs` — regenerate `public/whats-new.html` after editing `CHANGELOG.md` (user-facing entries go at the top). `node tools/make-privacy.mjs` — regenerate `public/privacy.html` (what's stored, what's downloaded) when that changes. `node tools/make-guide.mjs` — regenerate `public/guide.html` (camera setup, how the scoring is tested, what it can't do yet; its body is `tools/guide-body.html`, moved off the homepage in Nov 2026 to keep it short). All four share `tools/page-shell.mjs` (head, nav, footer copied from `index.html`) and have staleness tests in `npm test`; run `npm run sw` after. `node tools/make-og.mjs` redraws the share card `public/og.png`. `public/robots.txt` and `sitemap.xml` list clean URLs; add new pages there.
- `npm run deploy` — `npm run sw` + `wrangler deploy`

## How things fit
- `ui/live.js` owns the camera, the frame loop (requestVideoFrameCallback), HUD and controls; it feeds `Session.update(landmarks, aspect, t, world)` and turns events into the coach (`coach.js`) and speech queue (`speech.js`, gated to "not mid-rep").
- A `Session` starts unarmed (countdown / auto-start): it tracks, calibrates and reports `ready`, but counts nothing until `arm()`.
- Settings: `config.js` DEFAULTS → `ui/settings.js` (`cfg`, `setCfg`); controls bind declaratively with `data-setting` / `data-toggle`.
- Storage: one localStorage key (`workout-analyzer:v1`, name kept for old data), versioned (`VERSION` + `migrate()` in `storage.js`). Add fields with a migration + `tests/storage.test.mjs` case.
- Screens switch with `showScreen(id)` (View Transitions blur-fade; focus moves to the new screen's heading).
- The service worker is registered only by the trainer (see the note in `js/site/main.js`).

## Motion libraries (homepage)
- `js/site/smooth.js`: Lenis on GSAP's ticker, feeding ScrollTrigger; paused while a `<dialog>` is open; `data-lenis-prevent` scrolls natively. Lenis is added *first* in the ticker (`prioritize`): after GSAP's tween writes, moving the page forced a full style recalc twice a frame. In-page link glides go through `lenis.scrollTo` (`motion-nav.js`); Lenis already leaves `scroll-padding-top` above the target, so pass no offset. `landOnHash()` (motion-nav.js) re-lands `index.html#section` links from other pages each time the layout changes in the first seconds (the story and paths grow after load).
- `js/site/scroll-progress.js`: the one scroll measure for the homepage. `onScroll((s) => …)` gives `s.overall` and `s.sections[key].progress` / `.inside` (0–1; key = section id or `data-scroll`), `s.velocity`, `sectionAt(s, f)`. Layout is measured only on resize or a height change (ResizeObserver), never per frame. The rail, progress line, tones, nav-spy, sticky header and skill paths read it; `track(el, key)` adds an element. Pure math in `computeScroll` (tests/scroll.test.mjs). Don't add new scroll listeners that call getBoundingClientRect: use this.
- `js/site/stage.js`: a fixed WebGL canvas behind all homepage content (`.scroll-stage`, beside the rail), created on the first `useStage(setup)`; `setup(ctx)` returns a per-frame `(s, dt) => bool` (true = keep drawing) and may push backdrop passes onto `ctx.passes`; `ctx.width/height` hold its size (measured on resize: don't read layout per frame, the stage redraws every frame for the atmosphere). `?stage` loads `stage-placeholder.js` (a stand-in shape, depth rings, a readout).
- `js/site/atmosphere.js`: the smoke behind the whole page (a quarter-resolution noise pass on the stage), lit by the hero's live grade colour (the `vf:live` event from hero3d.js), and the ink over it (`js/site/ink.js`: stable fluids on half-float render targets; the pointer pours and stirs, scrolling stirs, random drops; off for reduced motion and on software GPUs). Keep the ink thin: the owner wants the background alive but text must stay readable (Nov 2026: calmed further, he found it distracting).
- `js/site/scenes.js`: the homepage scrolls *in* (≥1100 px, motion allowed): every section is one full-screen scene (plain sections wrapped in a sticky `.scene-frame` > `.scene-fit`, held half a screen and fitted; pinned ones rest where their stage fills the screen, rule sticky, story/paths heading moved into the pin as a `.scene-title` card). Boundaries reveal the next scene over the last through a clip-path shape with a glowing SVG edge (`makeEdge`): sweep, scan, portal, slats, horizon; later sections sit above earlier ones; the hero opens as a portal from its figure while hero3d swings via `scene-state.js`, each section gets `data-scene` (before / in / after) and css/site.css animates its heading letters, lead words and rule label in and out from it (scroll-fx.js and sections.js only use their one-off triggers when scenes are off), and a stop mid-transition glides to the nearer scene (`window.__vfNoSnap` turns that off for screenshots). Mounted after the ring, story and paths are built. `main` has `overflow: clip`; scroll-progress.js measures with offsetTop/offsetHeight so transforms never skew it; links land at scene tops (`scroll-padding-top: 0`).
- `js/site/ink-trail.js`: the ink trail down the margin where a screen is only words: homepage text scenes (scenes.js mounts one in each plain scene but #lab and #faq, fed with the scene's hold progress) and the info pages (library.js, whole page, a blot per h2).
- `js/site/ex-ring.js`: the exercises section as a 3D ring of all 18 cards (≥1000 px, motion allowed): moves the 5 `.ex-card`s and the 13 mini-plate links into a sticky stage, turns with the pinned scroll and on its own. expop.js now listens on `#exercises`, so ring cards open popups.
- `js/site/stage-body.js`: the figure in light at two stations (≥1280 px): a scroll-scrubbed squat beside the questions, half a jumping jack beside the closing band, in the free space measured beside the text (`textRight`, since SplitText makes headings full-width line boxes).
- `js/figures/glow.js`: the stick figure drawn in light (bones as a core + a halo tube, a ring head facing the camera, joint points, trails, a floor pool), used by the hero (`figure-gl.js`) and the stage. The owner prefers this stick figure: a realistic MakeHuman mannequin was built and dropped in Nov 2026 (git 931147c has it).
- `js/site/boot.js`: the calibration intro (first visit in a session; the inline script in index.html's head adds `html.booting` and gives up after 6 s). It dispatches `vf:booted`; the hero's intro and headline reveal wait for it. The e2e harness skips it unless `make({ boot: true })`.
- Page transitions: `css/transitions.css` + the inline `pagereveal` script in each page head: a circle from the click, .9 s, no blur (clip-path, transform, brightness only). index.html and the generated pages pre-render the trainer on hover (`<script type="speculationrules">`; DevTools/Playwright disables pre-rendering, so tests can't see it).
- Buttons: `js/ui/hover-fill.js` (the circle of ink from the pointer; `.btn::before` in site.css and app.css). The owner prefers it to the scanning beam tried in Nov 2026.
- Fast-scroll smoothness (Nov 2026, measured with the CPU throttled 4×): never start a GSAP tween mid-scroll on page elements (its first render reads computed style and, with scenes.js writing in the same frame, forces a full style recalc); start reveals with a class (CSS transitions) or the Web Animations API instead. Don't write inherited custom properties every frame (they restyle whole subtrees); don't query SVG geometry per frame (sample it once). With Lenis, scroll-progress.js updates at the end of GSAP's tick, after ScrollTrigger reads.
- `js/site/scroll-fx.js`: SplitText letter-by-letter reveals for headings, lead paragraphs lit word by word as their section lands (timed, not scrubbed: scenes.js holds sections still while they arrive), ScrollTrigger batch reveals for card groups, hero parallax on the way out.
- `js/site/story.js`: ScrollTrigger progress for the pinned 3D story.
- `js/figures/figure-gl.js`: the hero's figure in light (Three.js, glow.js) under the same camera as `figures/scene3d.js`, which still draws the floor, protractors and notes on 2D canvases.
- Removed Nov 2026 as template tells (DESIGN.md "Removed in Nov 2026"): click sparks, magnetic buttons, the fact ticker, tilting cards, decoding text, the pointer glow. Don't re-add them.
- Also on the homepage: `sections.js` (each section's instrument rule: N°, name, a hairline drawn by the scroll, a reading counted from the section), `card-reps.js` (cards do their rep on hover), `paths.js` (the pinned skill-path carousel; trees from `ui/mini-tree.js`), `progress.js` (header reading line), `faq.js`. The trainer's picker is a ring of cards on wide screens (`ui/picker-ring.js`, mounted by `ui/menu.js`; the dial below 1180 px); e2e opens exercises by focusing a card and pressing Enter, since the ring moves. The skill tree is 3D on wide screens (`ui/tree3d.js`, mounted by `ui/skills.js` `drawTree`; the flat tree is `drawTree2d`, also the fallback); its labels are the page's own buttons (`label3d`), so the same click handler (`wireTree`) serves both. Trainer moments live in `js/ui/flair.js` (card-to-panel morph, stamp, flip board, deal) and `ui/skills.js` (card-to-tree zoom).
- No custom cursor (removed at the owner's request: the Mac pointer kept showing).
- Not used, on purpose: React Bits, Kokonut UI, Componentry, Bklit UI (React/Tailwind components: port the idea instead); Motion and Anime.js (duplicate GSAP); Spline, Rive, Theatre.js (need scene files made in their own editors; if the owner makes one, self-host its runtime in `vendor/`); Manus (an AI agent, not a library).

## Overlay + voice
- `Session.update` returns `confidence`, `overlay` ("none" | "ready" | "rep"), `facing` ({dir, confidence, locked}) and `progress`. Frames below 0.45 confidence are never graded or counted. live.js fades skeleton/guide alphas toward the state.
- Guide geometry is pure (`js/guide.js`, raw image pixels); `mirrorGuide()` for the mirrored view; drawing in `ui/overlay.js drawGuide`.
- Speech: coach lines are PARTS (`[92, "phrase"]`); `voice.js` plays one clip per part on the Web Audio clock with `speech.js planLine` pauses; any missing clip → the whole line via Web Speech.

## Tests
- Simulated people: `tests/helpers/synth.mjs` (`repStream` supports rotation, 3D world landmarks, mutations, rests, custom motion profiles, irregular frame times).
- Real recordings: `tests/fixtures/*.json` + `.expect.json` (RECORDING_GUIDE.md). Synthetic ones are regenerated by `node tools/make-synthetic-fixture.mjs`.
- `?debug` exposes `window.__vfDebug` (live state) and `window.__vf` (`cfg`, `showResults(r)`) for the browser tests.
